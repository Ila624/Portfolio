# EcoBot — AI Energy Analyst Agent

EcoBot is a conversational AI agent that helps households understand their solar production and
energy consumption data. It was built for a fictional renewable energy community platform
(EcoGrid), whose customers had access to raw charts and numbers but struggled to interpret them.
Instead of a generic chatbot, EcoBot is a **data-driven agent**: it cleans messy IoT sensor data,
runs real calculations through tools, generates charts, and answers both data questions and
conceptual ones through retrieval-augmented generation (RAG).

## Features

- **Data cleaning** — detects and fixes missing values (broken sensors) and impossible negative
  readings in the raw CSV data before any analysis.
- **Data Q&A via tool-calling** — the agent doesn't guess numbers, it computes them: hourly,
  daily, weekly and total aggregations, surplus/deficit comparisons, anomaly detection (surplus
  days going to waste, unusually high consumption days).
- **Chart generation** — daily and weekly production vs. consumption charts, rendered inline in
  the chat, including follow-up requests ("and the week before that?").
- **RAG knowledge base** — answers conceptual questions ("why is my bill still high with solar
  panels?", "is a home battery worth it?") by retrieving from a small knowledge base of guides
  and FAQs, instead of relying only on the model's general knowledge.
- **Conversational memory** — follow-up questions are resolved using the conversation history
  (per-session thread), so the user doesn't need to repeat context.
- **Error handling** — automatic retry with exponential backoff on LLM rate-limit errors, so a
  transient `429` doesn't break the conversation.

## How it works

```
                    ┌─────────────────────┐
  User question ───▶│   LangGraph agent    │
                    │  (Groq LLM, tool-    │
                    │   calling loop)      │
                    └─────────┬───────────┘
                              │ picks a tool
          ┌───────────────────┼───────────────────────┐
          ▼                   ▼                        ▼
 ┌─────────────────┐ ┌─────────────────┐    ┌───────────────────────┐
 │  Data tools      │ │  Chart tool      │    │  RAG tool              │
 │  (pandas over    │ │  (matplotlib,    │    │  search_knowledge_base │
 │  cleaned CSVs)   │ │  saved as PNG)   │    │  (see pipeline below)  │
 └─────────────────┘ └─────────────────┘    └───────────────────────┘
```

**RAG retrieval pipeline** (3 stages, to handle both vocabulary mismatch and ranking quality):

1. **`MultiQueryRetriever`** — the LLM generates 3 reformulations of the user's question
   (synonyms, different phrasing) so the search isn't limited to the user's exact wording.
2. **FAISS** — retrieves the most similar chunks (embeddings) for each reformulation, merging
   and deduplicating the results.
3. **Cross-encoder reranking** — a local cross-encoder re-scores the merged candidates against
   the *original* question and keeps only the top 5 most relevant passages, which are handed to
   the agent.

All embeddings and the reranker run **locally** (`sentence-transformers`), so the only external
API used is the LLM provider (Groq) — no extra API keys required for the knowledge base.

## Tech stack

**Python** · **LangChain** / **LangGraph** (agent, tool-calling, memory) · **Groq** (LLM
inference) · **Streamlit** (chat UI) · **Pandas** / **Matplotlib** (data analysis & charts) ·
**FAISS** (vector store) · **Sentence-Transformers** (embeddings + cross-encoder reranking) ·
**python-dotenv** (secrets management)

## Running it locally

```bash
pip install -r requirements.txt
```

Create a `.env` file with a free [Groq](https://console.groq.com) API key:

```
GROQ_API_KEY=your-key-here
```

Then run the app:

```bash
streamlit run app.py
```

Upload the two demo CSVs (generated by running the notebook) from the sidebar, and start asking
questions in the chat.

> On first use, the RAG tool downloads two small models from Hugging Face (embeddings +
> cross-encoder, ~90MB each) — this requires internet access only once; they're cached locally
> after that.

## Example questions

- *"Show me a chart of weekly production and consumption."*
- *"Which week had the highest production?"*
- *"What day had the biggest deficit?"*
- *"And the week before the one you showed me?"* (tests conversational memory + chart follow-up)
- *"Is it worth installing a home battery?"* (tests the RAG tool)
- *"Can I earn something by selling the electricity my neighbors don't use?"* (tests RAG with
  vocabulary not present in the source documents — see `faq_tariffe_cer.md`)

## Notes

- The two documents in `knowledge_base/` are demo content written for this project (no real
  EcoGrid documentation was provided); in a real deployment they'd be replaced with the
  company's actual guides, FAQs and contract terms.
- The dataset is synthetic, generated on first run with a fixed random seed over a rolling
  30-day window ending "today" — exact figures will differ slightly depending on the day the
  notebook is executed.
- Built as part of an AI agents course project (single-agent architecture with LangChain,
  chosen over a multi-agent setup given the scope of the task).
